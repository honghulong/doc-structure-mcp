## 1. 项目定位

**扫描型 PDF → 结构化 DOCX**，专注扫描件的正文排版还原。

- 输入：扫描型 PDF（含红头文件的扫描件）
- 输出：.docx 格式，保留阅读顺序、标题层级、段落结构
- 排除：发票 OCR（已迁移至 `ocr-invoice-mcp` 项目）
- 流程：验证 → 测试 → 部署（Colab 优先）

## 3. 技术架构

```
PDF → PyMuPDF转图片 → PaddleOCR → XY-Cut排序 → docx_builder → DOCX
```

| 组件 | 文件 | 职责 |
|------|------|------|
| Web 服务 | `src/doc_service.py` | HTTP 接口（8768），接收 PDF 返回 DOCX |
| 排版引擎 | `src/docx_builder.py` | XY-Cut 排序、红头文字、标题检测、段落合并、签章页处理 |
| 测试脚本 | `tests/test_*.py` | 算法验证，可在 Colab 上直接运行 |

### 3.1 排版算法（XY-Cut）

- **正文区域：** 横向 XY-Cut（先按 Y 坐标分组为行，行内按 X 排序）
- **红头区域：** 竖排框检测（h > w*2）→ 逐字分行 → 红色字体
- **标题检测：** 正则规则 + 发文关键词 + 短行判断
- **段落合并：** 连续正文行自动合并（以句号/分号结尾切换段落）
- **签章页：** 短行密集 + 低置信度 → 自动留空

### 3.2 OCR 配置

```
检测模型: PP-OCRv5_mobile_det  (阈值 0.3)
识别模型: PP-OCRv5_mobile_rec
```

### 3.3 红头文字处理策略

红头竖排文字检测框特征：`高度 > 宽度 × 2`（典型的竖排框）。

处理流程：
```
OCR原始框 → 筛选竖排框(h>w*2) → 列分组(x/60取整) → 拆字 → 逐字输出(红色)
```

竖排框内的文字是 OCR 合并后的结果（如 "财税中国国国"），通过逐字拆分 + 相邻去重还原为单字，每字独立段落。

```

```
